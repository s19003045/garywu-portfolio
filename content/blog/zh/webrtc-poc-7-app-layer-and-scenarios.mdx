[上一篇](/zh/blog/webrtc-poc-6-media-plane-build-vs-adopt)把媒體層的抉擇講完了。但如果你以為「選好 LiveKit 就差不多了」，那會錯得很遠。

媒體層只是地基。**使用者真正感受到的產品價值，幾乎都在應用層**：怎麼登入、怎麼建會議、誰能進、連結怎麼分享、排程怎麼運作。這一層，無論你媒體選自建還是採用，**都得自己寫**——因為它就是你的產品本身。

## 不管媒體選誰，這層都要自己寫

把我們一開始想要的功能攤開，會發現它們全都落在應用層，跟媒體層幾乎無關：

- **身分與帳號**：Google 登入（OIDC）→ 建立你自己的 user 與 session。
- **會議是一等公民**：用資料庫（如 Postgres）存 meeting（id、代碼、主持人、密碼、有效期、設定）。「分享連結」= 分享 meeting 代碼；「建立連結」= 開一筆 meeting record。
- **預先建立 / 排程**：同一張 meeting 表加排程時間、週期性、行事曆整合，連結可以先建好、時間到才可進。
- **權限與角色**：主持人 / 共同主持 / 參與者 / 觀看者；候診室（lobby）、鎖房、踢人、強制靜音。

而這一切，會在你 Phase 6 已經有的東西上自然長大：**入會 token 從「房間級」進化成「身分 + 房間 + 角色 + 能力」級**。Phase 6 的 SFU 已經會驗 token 裡的 `room`，自然延伸成驗 `role` 與權限。媒體層（LiveKit 或自建）只負責「放不放行、能不能發送」，**決定權限的是你的應用層**。

## 媒體層之外的架構

```
 Google ──OIDC──▶ ┌───────────────┐  會議/使用者/權限  ┌──────────┐
 使用者 ◀─session─│  Auth/API 服務 │◀─────────────────│ Postgres │
        │ 帶 token │ 建立會議/排程/  │                  └──────────┘
        ▼         │ 簽發媒體 token  │  token + 節點位址
   媒體層(LiveKit 或自建 SFU 叢集) ── 錄影/egress → 物件儲存 / CDN
```

新主角是 **Auth/API 服務**（做登入、管會議與權限、簽媒體 token）和**資料庫**（會議與權限的真實來源；Redis 只適合放可過期的即時狀態，不適合當會議的本體）。注意這層**跟你媒體層選什麼完全解耦**——這也是為什麼它最值得你自己投資。

## 情境如何重塑這一層

同樣是「應用層」，三個場景要的東西差很多：

**開放大型（Meet 類）**
- 身分：Google / 社群登入，要低摩擦。
- 連結：任何人可建房、用代碼分享、訪客可進。
- 重點：消費級 UX、**濫用防護**（rate limit、防洗版、防騷擾）、客訴與檢舉機制。

**資安嚴謹大廠**
- 身分：**企業 SSO（自家 IdP，通常不是 Google）**，綁公司目錄。
- 安全：**E2EE、資料落地/地端、完整稽核 log、裝置管控**；錄影可能直接禁止或嚴格治理。
- 連結：不可公開、僅限內部、可能要再次驗證身分才進。

**萬人演唱會**
- 身分：**票券驗證**（買了票才能看），不是傳統帳號。
- 規模：觀眾數十萬，重點在 **CDN 成本**與並發承載。
- 功能：DVR / 回放、聊天與互動要能撐住海量人數（通常另走一套訊息系統）。

## 一張表收束三個場景

| 面向 | 開放大型（Meet） | 資安大廠 | 萬人演唱會 |
|---|---|---|---|
| 規模形狀 | 很多中小房（A） | 中小房、高敏感 | 單一大房（B） |
| 媒體層 | 採用 LiveKit | LiveKit 地端 + TURN | 廣播 LL-HLS/CDN |
| 身分 | Google 登入 | 企業 SSO | 票券驗證 |
| 合規 | 一般 | E2EE / 地端 / 稽核 | 版權 / 票務 |
| 最大成本 | 節點規模 | 合規與維運 | CDN 流量 |
| 連結語意 | 公開、易分享 | 內部、受控 | 票 = 入場權 |

同一個「視訊系統」的字眼，背後其實是三個不同的產品。

## 整個系列最後想說的

回頭看這趟從 Phase 1 到 Phase 6、再到這三篇決策文，我最大的收穫不是「學會了 SFU」或「學會了 LiveKit」，而是一個更上層的判斷力：

**從 POC 到產品，最重要的不是把某個技術練到極致，而是先把目標與情境問清楚，再讓目標去挑技術。**

自建到 Phase 6，讓我有能力看懂每個選項在解什麼；而把三個場景攤開，讓我看見同一套知識會導出三種架構。技術是手段，目標才是方向——這大概是這整個系列，從「開鏡頭」一路走到「怎麼抉擇」，最想留下的一句話。

## 名詞小抄

- **OIDC**：OpenID Connect，建立在 OAuth2 上的身分驗證協定，Google 登入即屬此類。
- **SSO**：單一登入，企業常用自家身分提供者（IdP）統一登入。
- **E2EE**：端對端加密，連伺服器都看不到媒體內容。
- **IdP**：Identity Provider，身分提供者（如企業目錄、Google）。
- **DVR**：直播過程中可回看的錄影/時移功能。
