## 專案背景

Rock System 是我一手規劃、建置與長期維護的全端業務系統，目標是提供地政士事務所可實際落地使用的資訊平台。整體系統涵蓋前端操作介面、後端 API 與業務邏輯、資料庫設計、權限與授權機制，以及 Docker 化部署流程，並支援後續版本演進與維運。

- **前端**以 React、TypeScript、Refine 與 Material UI 建構，負責案件管理、收費管理、零用金、報表、權限呈現與日常作業流程。
- **後端**以 Strapi v4 + TypeScript 為核心，串接 PostgreSQL，承接資料模型、認證授權、席位管理、心跳同步與業務 API。
- **部署**採容器化方式，讓系統能在客戶環境中穩定交付、更新與維護。

## 核心挑戰

這個專案的難點不只是把前後端做出來，而是要把一套真正能營運的商業系統從 0 到 1 落地。

### 1. 業務流程複雜

案件管理、收費、交易、角色權限、零用金、報表與文件輸出彼此高度關聯，資料欄位多、流程狀態多，且不同客戶對流程與權限的要求並不一致——系統必須同時兼顧**彈性**與**資料一致性**。

### 2. 權限與授權控制

這不只是一般登入驗證，而是包含細粒度頁面與動作權限、不同客戶的權限差異、席位限制、授權狀態同步，以及離線寬限與會話心跳等機制，必須同時兼顧**安全性、可維護性與使用者體驗**。

### 3. 交付與維運

由於需要支援 Docker 化部署與後續維護，從一開始就不能只考慮開發階段，而要連同環境變數管理、資料庫持久化、服務啟停、版本更新、錯誤診斷與文件化一起設計。

## 我的角色與貢獻

我以**單一主責工程師**的角色負責整個 SDLC，從需求理解、系統設計、資料模型規劃、前後端開發、部署方案設計，到後續維護與功能迭代都由我主導。

- 規劃整體系統架構，拆分前端、後端、資料庫與部署層的責任邊界
- 以前端角度建立可擴充的模組化架構，整合案件管理、表單、權限、報表、PDF 與多種業務流程頁面
- 以 Strapi + TypeScript 設計後端內容模型、API 與業務邏輯，並承接 PostgreSQL 資料持久化
- 實作授權管理、席位控管、會話心跳、離線寬限、Firebase 登入與 2FA 等安全與身份驗證流程
- 設計以**環境變數驅動的權限配置機制**，讓不同客戶在相同主系統下套用不同權限規則
- 建立 Docker 與 Docker Compose 部署方式，讓前端、後端與 PostgreSQL 一致化交付
- 持續維護文件、測試腳本與問題診斷流程，支撐後續版本更新與營運維護

## 技術成果

Rock System 最具代表性的成果，不是單一功能，而是建立出一套**可長期維運的全端產品能力**。

**前端**：以 React + TypeScript 為基礎的企業內部系統架構，支援大量表單、資料表格、條件式欄位、案件流程頁、報表、PDF 匯出與多模組整合，並導入權限控制、多語系、狀態管理與 UI 元件一致性，降低後續擴充成本。

**後端**：以 Strapi 為基底延伸出更貼近商業場景的 API 與管理能力，包含授權狀態查詢、心跳同步、使用者活動追蹤、Firebase 登入、2FA、會話控管、使用量回報等模組，讓系統不只是 CRUD 平台，而是可支撐商業運行的後端服務。

**系統整合**：完成前端、後端與 PostgreSQL 的容器化部署，讓專案具備可複製的交付模式，也便於後續在不同環境安裝、更新與維護。對需要長期營運的內部系統來說，這代表專案從開發階段就已具備**產品化思維**。

## 學習與反思

這個專案讓我更明確理解：全端能力不只是會寫前端與後端，而是要能把需求、資料結構、權限模型、部署方式與維運流程，整合成一個可長期運作的系統。真正困難的地方通常不是某一支 API 或某一頁 UI，而是如何在功能持續增加的情況下，依然維持架構清楚、資料一致、部署穩定，並讓後續維護成本可控。

另一個重要收穫是更重視「**產品化的工程思維**」：權限配置不能只寫死在程式碼裡、授權機制不能只考慮線上情境、部署流程不能只停留在本機可跑。這些看似偏維運或偏架構的決策，實際上直接影響產品能不能穩定交付。

若未來再進一步優化，我會持續補強自動化測試覆蓋率、監控與告警能力，以及更明確的模組邊界，讓整體系統在持續迭代下仍維持可預期的品質與延展性。
